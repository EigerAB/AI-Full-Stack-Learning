# Agent 开发学习体系

> 面向背景：前端开发经验较强，掌握 Python / FastAPI，已经学习过 Zeno Agent Platform 的部分运行链路，希望进一步具备 Agent Runtime 与 Agent Platform 的设计、开发能力。

## 学习目标

这套课程不以“会调用某个 Agent SDK”为最终目标，而是要求能够：

1. 从零实现一个最小但完整的 Agent Runtime；
2. 解释 Model、Context、Tool、Memory、Workflow 与 Multi-Agent 的职责边界；
3. 设计可暂停、恢复、重试、追踪和评测的长任务系统；
4. 阅读并比较不同 Agent 框架的核心抽象与架构取舍；
5. 设计具备多租户、权限、安全、可观测性和评测能力的 Agent Platform；
6. 从前端交互一路追踪到模型、工具和持久化层，定位 Agent 链路故障。

## 两条学习路线

| 路线 | 定位 | 优势 | 主要风险 | 建议用途 |
|---|---|---|---|---|
| [架构优先型学习路线](./Agent架构与平台开发学习路线.md) | 从 Runtime 原理逐层构建平台能力 | 知识可迁移、能读源码、能做平台 | 前期反馈略慢 | **主线，推荐** |
| [框架优先型学习路线](./Agent框架优先型学习路线.md) | 先用成熟框架完成应用，再反推内核 | 快速做出完整项目 | 容易停留在 API 使用层 | 辅线与实践加速器 |

框架与协议的当前选型依据见 [2026 框架生态研究](./framework-landscape-research.md)。该文只采用官方文档、官方仓库与正式协议规范，并用于记录易随时间变化的内容。

## 推荐组合方式

不要完整学完一条路线再开始另一条。建议采用“一条主线、一个对照实验”的方式：

```text
架构主线学习一个核心概念
        ↓
用主框架实现同一能力
        ↓
阅读 Zeno 对应生产代码
        ↓
比较三者的数据模型、控制流和失败语义
        ↓
把结论沉淀到自己的 Mini Runtime
```

建议节奏：

- 第 1 阶段：架构主线 00～03，同时完成框架路线 00～03；
- 第 2 阶段：架构主线 04～09，同时完成框架路线 04～07；
- 第 3 阶段：架构主线 10～13，同时完成框架路线的生产化部分；
- 第 4 阶段：源码对比与毕业项目，不再增加新框架。

## 每节课的统一完成标准

每节课不是“看过文档”就算完成，至少包含以下六项：

1. **概念模型**：能够画出组件边界和数据流；
2. **最小实验**：用尽量少的代码验证核心机制；
3. **源码定位**：在框架或 Zeno 中找到对应实现；
4. **失败实验**：主动制造超时、坏参数、空响应等故障；
5. **设计复盘**：解释当前设计的收益、代价与替代方案；
6. **检索题**：面对一个现象，能够判断最可能出错的层级。

每个模块最终应留下四种成果：

- 一篇结构化学习记录；
- 一份可运行代码；
- 一组自动化测试；
- 一张架构或时序图。

## 贯穿课程的项目

统一使用一个逐步演进的 **Engineering Copilot Platform**：它可以读取项目资料、检索代码、调用受控工具、执行工作流，并把运行过程实时展示在前端调试台中。

项目按四个里程碑演进：

- **M1 — Runtime**：单 Agent、Tool Calling、流式事件、预算与终止条件；
- **M2 — Intelligence**：Context、Memory、RAG 与结构化输出；
- **M3 — Orchestration**：Workflow、Multi-Agent、Suspend / Resume；
- **M4 — Platform**：多租户、版本、Trace、Eval、安全、发布与治理。

技术栈保持克制：Python、FastAPI、Pydantic、PostgreSQL，加一个主 Agent 框架用于对照。只有当课程目标需要时才增加向量库、消息队列和分布式执行组件。

## 与 Zeno 课程的关系

现有课程继续保留在 `learning/projects/zeno-platform`，其角色从“知识体系主线”调整为“生产代码案例库”：

| 已有课程 | 放入新体系的位置 |
|---|---|
| 两阶段 Chat 协议 | 事件协议与 Human-in-the-loop |
| Chat Service 调用链 | Agent Platform 请求与执行链路 |
| Agent Loop | Agent Runtime 内核 |
| Tool 执行层 | Tool System |
| Workflow DSL | Workflow Engine |
| SubAgent / Team Runtime | Multi-Agent Runtime |

学习新模块时再回看对应 Zeno 实现，重点回答：它解决了什么生产约束、为什么没有采用更简单的设计、失败时会呈现什么现象。

## 学习原则

- 先掌握不随框架变化的抽象，再记具体 API；
- 同一个能力至少看三种实现：手写最小版、成熟框架版、Zeno 生产版；
- 优先学习失败语义、状态模型和边界条件，而不只关注成功示例；
- 不为展示技术栈而引入基础设施；
- 单 Agent 能解决的问题，不提前使用 Multi-Agent；
- 没有 Eval 和 Trace 的 Agent 功能，不视为完成。

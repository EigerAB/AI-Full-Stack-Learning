## 1. 函数式组件基础

React 函数组件本质上就是一个**返回 JSX 的纯函数**：`(props) => JSX.Element`。每次状态或 props 变化，React 都会重新调用这个函数（重新渲染），而不是像 Vue 那样通过响应式代理精确追踪依赖再局部更新。

### 1.1 Props 与 TypeScript 类型

```tsx
export interface CategoryTableProps {
  extraToolbarRight?: React.ReactNode;
  onSelect?: (id: string) => void;
}

const CategoryTable = ({ extraToolbarRight, onSelect }: CategoryTableProps) => {
  return <div>{extraToolbarRight}</div>;
};
```

- 用 `interface` 定义 Props（项目内统一风格），可选属性用 `?`。
- `children` 类型用 `React.ReactNode`；如果是渲染函数用 `(item: T) => React.ReactNode`。
- 事件回调类型直接写函数签名，如 `onClick?: (id: string) => void`，避免用 `Function` 之类的宽泛类型。

### 1.2 组件组合模式

React 没有 Vue 的插槽（slot），组合能力通过 **props 传组件 / children / render props** 实现：

```tsx
// 类似具名插槽：把 ReactNode 作为 prop 传入
<PageContainer extraToolbarRight={<Button icon={<PlusOutlined />}>新建</Button>} />

// 类似默认插槽：children
<Modal title="确认删除">
  <p>此操作不可恢复</p>
</Modal>
```

### 1.3 forwardRef（父组件获取子组件实例/方法）

Vue 里父组件可以直接用 `ref` 拿到子组件暴露的方法（`defineExpose`）。React 中默认组件不暴露内部状态/DOM，需要 `forwardRef` + `useImperativeHandle`（后面详细讲）。

## 2. 状态与 Hooks（核心）

> Hooks 只能在函数组件顶层或自定义 Hook 中调用，不能写在条件、循环、嵌套函数里（"Hooks 规则"），因为 React 靠**调用顺序**而不是名字来匹配每次渲染的 state。

### 2.1 `useState` —— 组件内部状态

```tsx
const [count, setCount] = useState(0);
const [categories, setCategories] = useState<ProductCategory[]>([]);
```

要点：

- **每次 `setState` 都会触发重新渲染**（除非新旧值 `Object.is` 相等）。
- **函数式更新**：当新状态依赖旧状态时，用回调形式，避免闭包拿到过期值：
  ```tsx
  setCount((prev) => prev + 1); // 推荐，尤其在异步/多次调用场景
  setCount(count + 1); // 可能读到旧的 count（连续调用时会有坑）
  ```
- **惰性初始化**：初始值计算成本较高时，传函数而不是直接调用，避免每次渲染都执行：
  ```tsx
  const [tree, setTree] = useState(() => buildExpensiveTree(rawData));
  ```
- **对象/数组必须不可变更新**（和 Vue 的 `reactive` 直接改属性完全不同，React 靠引用变化判断是否更新）：
  ```tsx
  // 错误：直接 mutate，React 不会重新渲染
  selectedIds.add(id);
  setSelectedIds(selectedIds);

  // 正确：创建新引用
  setSelectedIds(new Set(selectedIds).add(id));
  setCategories((prev) => prev.map((c) => (c.id === id ? { ...c, name } : c)));
  ```

### 2.2 `useReducer` —— 复杂状态逻辑

当一个组件里有多个相互关联的状态（比如表单的多个字段联动、一个"状态机"式的流程），`useReducer` 比一堆 `useState` 更清晰，类似 Vuex/Pinia 的 `dispatch(action)` 思路，但作用域仅限组件内部：

```tsx
type State = { step: number; formData: Record<string, unknown> };
type Action =
  | { type: 'next' }
  | { type: 'prev' }
  | { type: 'setField'; key: string; value: unknown };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'next':
      return { ...state, step: state.step + 1 };
    case 'prev':
      return { ...state, step: state.step - 1 };
    case 'setField':
      return { ...state, formData: { ...state.formData, [action.key]: action.value } };
  }
}

const [state, dispatch] = useReducer(reducer, { step: 0, formData: {} });
dispatch({ type: 'next' });
```

**选型建议**：状态之间独立、简单 → `useState`；状态之间有复杂联动/多种更新方式 → `useReducer`。

### 2.3 `useEffect` —— 副作用（对应 Vue 的 `watch` + 生命周期钩子）

```tsx
useEffect(() => {
  fetchCategories();
}, [fetchCategories]); // 依赖数组

useEffect(() => {
  const timer = setInterval(() => refresh(), 5000);
  return () => clearInterval(timer); // 清理函数：卸载或依赖变化前执行
}, []);
```

依赖数组决定执行时机：

| 依赖数组 | 执行时机 | 类比 Vue |
|---|---|---|
| 不传 | 每次渲染后都执行 | 无直接对应，慎用 |
| `[]` | 仅挂载后执行一次 | `onMounted` |
| `[a, b]` | 挂载后 + a/b 变化后执行 | `watch([a, b], ...)` |
| 有 return 的清理函数 | 组件卸载 或 下次 effect 执行前调用 | `onUnmounted` / watch 的清理 |

**常见陷阱**：

1. **闭包陈旧值（stale closure）**：effect 内部引用的变量是"创建这个 effect 时"的快照，依赖数组没写全会读到旧值。
   ```tsx
   useEffect(() => {
     console.log(count); // 永远是初始值 0
   }, []); // 缺少 count 依赖
   ```
   解决：把用到的变量加入依赖数组，或使用函数式更新 `setCount(c => c + 1)` 规避读取闭包值。

2. **无限循环**：effect 里 setState 且依赖了每次渲染都变化的引用（如内联对象/数组/函数），会导致无限重渲染。用 `useCallback`/`useMemo` 稳定引用，或精简依赖。

3. **useEffect 依赖 ESLint 规则**：项目已装 `eslint-plugin-react-hooks`，务必让 `exhaustive-deps` 规则通过，不要为了"省事"用 `// eslint-disable-next-line`。

### 2.4 `useLayoutEffect` —— 同步副作用

与 `useEffect` 签名一致，区别是**执行时机**：`useLayoutEffect` 在浏览器绘制（paint）之前同步执行，`useEffect` 在绘制之后异步执行。

- 需要**读取/修改 DOM 布局**（如测量元素尺寸后立刻调整样式，避免闪烁）时用 `useLayoutEffect`。
- 其余场景（数据请求、订阅、日志）一律用 `useEffect`，避免阻塞渲染。

### 2.5 `useRef` —— 引用与可变值

两大用途，Vue 中 `ref` 只对应第一种（DOM 引用），第二种是 React 特有：

```tsx
// 1. 获取 DOM 节点
const inputRef = useRef<HTMLInputElement>(null);
<input ref={inputRef} />
inputRef.current?.focus();

// 2. 保存跨渲染周期的可变值，且修改它不会触发重新渲染
const timerRef = useRef<ReturnType<typeof setTimeout>>();
timerRef.current = setTimeout(() => {}, 1000);
```

对比 `useState`：`useState` 改变会重渲染并且值是"渲染快照"；`useRef.current` 改变不会重渲染，且是"实时可变"的，适合存 timer id、上一次的值、不需要展示的中间变量。

### 2.6 `useMemo` / `useCallback` —— 缓存

```tsx
// 缓存计算结果：依赖不变时不重新计算
const displayedCategories = useMemo(() => {
  const keyword = nameFilter.trim().toLowerCase();
  return keyword ? filterCategoryTree(categories, keyword) : categories;
}, [categories, nameFilter]);

// 缓存函数引用：避免子组件（尤其是被 memo 包裹的）因为引用变化而重新渲染
const handleDelete = useCallback(
  (categoryId: string) => {
    /* ... */
  },
  [fetchCategories],
);
```

- `useCallback(fn, deps)` 本质是 `useMemo(() => fn, deps)` 的语法糖。
- **不要滥用**：`useMemo`/`useCallback` 本身也有开销（比较依赖数组），只在以下场景使用：
  - 计算成本高（大数组处理、复杂过滤/排序）；
  - 作为 `useEffect` 依赖，需要稳定引用防止无限循环；
  - 传给 `React.memo` 包裹的子组件作为 props，防止无意义重渲染。
- React 19 引入了 **React Compiler**（详见性能优化章节），未来很多手动 memo 场景可以省略。

### 2.7 `useContext` —— 跨层级传值

对应 Vue 的 `provide`/`inject`。详见第 4 章。

### 2.8 `forwardRef` + `useImperativeHandle` —— 暴露命令式方法

Vue 的 `defineExpose` 在 React 里对应这两个搭配使用：

```tsx
export interface CategoryTableRef {
  handleCreate: () => void;
}

const CategoryTable = forwardRef<CategoryTableRef, CategoryTableProps>(
  ({ extraToolbarRight }, ref) => {
    const handleCreate = useCallback(() => {
      setModalVisible(true);
    }, []);

    // 只把 handleCreate 暴露给父组件，隐藏其余内部状态
    useImperativeHandle(ref, () => ({ handleCreate }), [handleCreate]);

    return <div>...</div>;
  },
);

// 父组件使用
const tableRef = useRef<CategoryTableRef>(null);
<CategoryTable ref={tableRef} />;
<Button onClick={() => tableRef.current?.handleCreate()}>新建</Button>;
```

> 注：React 19 起，函数组件可以**直接把 `ref` 当作普通 prop 接收**，不再强制要求 `forwardRef`（但配合 `useImperativeHandle` 暴露自定义方法时依然常用这个组合，antd 生态和现有项目代码也仍以 `forwardRef` 为主，可继续沿用）。

### 2.9 `useTransition` / `useDeferredValue` —— 并发特性

用于**大量数据渲染或高频输入**场景下，把"不紧急"的更新标记为低优先级，避免卡顿输入框：

```tsx
const [isPending, startTransition] = useTransition();
const [searchInput, setSearchInput] = useState('');
const [filteredList, setFilteredList] = useState(fullList);

function handleChange(value: string) {
  setSearchInput(value); // 紧急更新：输入框立刻响应
  startTransition(() => {
    setFilteredList(fullList.filter((i) => i.name.includes(value))); // 非紧急，可被打断
  });
}
```

`useDeferredValue` 是更轻量的替代方案，直接对一个值做"延迟"：

```tsx
const deferredKeyword = useDeferredValue(nameFilter);
const displayed = useMemo(() => filterCategoryTree(categories, deferredKeyword), [categories, deferredKeyword]);
```

两者都不阻塞 UI，`isPending` 可用来展示 loading 态（比如给 antd `Spin` 用）。

### 2.10 React 19 新增 Hooks（表单/异步相关）

这些主要面向"表单提交 + Server Actions"场景，在纯前端（无 RSC）项目中使用有限，但了解概念很有用：

- **`use()`**：可以在渲染中直接"读取"一个 Promise 或 Context，替代部分 `useContext`/数据获取场景。**注意**：`use()` 可以在条件语句中调用（不受 Hooks 规则限制），但通常配合 Suspense 使用，纯 CSR + antd 项目里用得较少，更多是数据请求场景的替代方案。
- **`useActionState`**（原 `useFormState`）：管理表单 action 的状态和返回结果，适合原生 `<form action={fn}>` 场景；用 antd `Form` 的项目一般还是用 `Form.onFinish` + 自己的 loading state 更顺手。
- **`useOptimistic`**：在异步操作（如删除一行）确认前，先乐观更新 UI，请求失败再回滚，适合列表的即时反馈场景。
- **`useFormStatus`**：在表单子组件内获取父 `<form>` 的提交状态（pending），用于禁用按钮等。

> 结论：在 antd + axios 的传统 CRUD 后台项目中，日常仍以 `useState` + `try/catch/finally` 手动管理 loading/error 为主；这几个新 Hook 更适合原生表单 + React Server Components/Actions 的项目形态，先了解概念即可，非必须马上迁移。

### 2.11 自定义 Hook —— 逻辑复用

命名必须以 `use` 开头（React 靠这个约定 + eslint 规则识别 Hook）。相当于 Vue 的组合式函数（composable）。

```tsx
// useTableRequest.ts：封装"请求 + loading + 分页"的通用逻辑
function useTableRequest<T>(fetcher: () => Promise<{ data: T[] }>) {
  const [data, setData] = useState<T[]>([]);
  const [loading, setLoading] = useState(true);

  const reload = useCallback(() => {
    setLoading(true);
    fetcher()
      .then((res) => setData(res.data))
      .catch(() => message.error('加载失败'))
      .finally(() => setLoading(false));
  }, [fetcher]);

  useEffect(() => {
    reload();
  }, [reload]);

  return { data, loading, reload };
}

// 使用
const { data: categories, loading, reload } = useTableRequest(getCategoryTree);
```

## 3. 生命周期（函数组件视角）

函数组件没有 `mounted`/`updated`/`unmounted` 这种显式生命周期方法，全部通过 `useEffect`（或 `useLayoutEffect`）的依赖数组来模拟：

```tsx
useEffect(() => {
  console.log('mounted'); // 相当于 onMounted
  return () => console.log('unmounted'); // 相当于 onUnmounted
}, []);

useEffect(() => {
  console.log('nameFilter 变化了'); // 相当于 watch(nameFilter, ...)，且首次挂载也会执行一次
}, [nameFilter]);
```

**React 19 严格模式（`<StrictMode>`）注意事项**：开发环境下，为了帮助发现副作用中的问题，React 会对组件**故意多挂载/卸载一次**（effect 会执行 → 清理 → 再执行），生产构建不会这样。因此：

- 不要假设 `useEffect` 只执行一次；
- 清理函数必须真正"清理"资源（取消订阅、clearTimeout 等），否则开发环境会看到重复请求等"假 bug"。

## 4. 上下文与组件级状态

> 仅从单个/一组组件角度讲 Context 用法，不涉及 Redux/Zustand 等项目级全局状态方案的搭建。

对应 Vue 的 `provide`/`inject`，用于避免逐层透传 props（prop drilling）：

```tsx
// ThemeContext.tsx
interface ThemeContextValue {
  mode: 'light' | 'dark';
  toggle: () => void;
}
const ThemeContext = createContext<ThemeContextValue | null>(null);

export function ThemeProvider({ children }: { children: React.ReactNode }) {
  const [mode, setMode] = useState<'light' | 'dark'>('light');
  const value = useMemo(
    () => ({ mode, toggle: () => setMode((m) => (m === 'light' ? 'dark' : 'light')) }),
    [mode],
  );
  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>;
}

export function useTheme() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error('useTheme 必须在 ThemeProvider 内使用');
  return ctx;
}

// 使用方（任意深度的子组件）
const { mode, toggle } = useTheme();
```

**性能注意点**：

- `Provider` 的 `value` 一旦引用变化，**所有消费该 Context 的子组件都会重新渲染**（无论子组件是否用到变化的那部分数据），所以 `value` 要用 `useMemo` 包裹，避免每次渲染都创建新对象。
- Context 粒度尽量拆小（比如把"频繁变化的值"和"稳定的方法"拆成两个 Context），避免无关组件被拖累重渲染。
- Context 不是响应式的"细粒度依赖追踪"（不像 Vue 的 `reactive`），它是"整体订阅、整体通知"，这是与 Vue 心智模型差异最大的地方之一。

## 5. 性能优化

### 5.1 `React.memo` —— 组件级别的"跳过重渲染"

```tsx
const CategoryRow = React.memo(function CategoryRow({ category }: { category: ProductCategory }) {
  return <tr>{category.name}</tr>;
});
```

- 默认对 props 做浅比较（shallow compare），props 引用不变则跳过重渲染。
- 只有在**父组件频繁重渲染、子组件渲染成本较高**时才有必要包裹，不要无脑全局套用。
- 配合 `useCallback`/`useMemo` 才有意义：如果传给它的 props 里有内联函数/对象，每次都是新引用，`memo` 直接失效。

### 5.2 列表渲染的 `key`

```tsx
{categories.map((c) => (
  <Row key={c.categoryId} category={c} /> // 用稳定唯一 id，而不是 index
))}
```

用 `index` 作为 key 在列表会增删/排序时会导致状态错乱（和 Vue 的 `:key` 要求完全一致）。antd `Table` 的 `rowKey` 同理。

### 5.3 组件拆分

把频繁变化的状态（如输入框的实时值）隔离到**独立的小组件**里，避免其变化连带整个大表格/表单一起重渲染。这是 React 里最实用、性价比最高的优化手段，往往比加一堆 `useMemo` 更有效。

### 5.4 React Compiler（React 19 生态新特性）

React 19 配套推出了 **React Compiler**（编译时自动优化），可以静态分析组件代码，自动插入等效于 `useMemo`/`useCallback`/`React.memo` 的优化，减少手写记忆化的心智负担。需要单独安装 babel 插件/vite 插件启用，属于渐进增强，**现阶段本项目未启用，手写 memo 仍然是主要优化手段**，了解即可。

## 7. 速查表 / 常见坑

### 7.1 Hook 选型速查

| 需求 | 用什么 |
|---|---|
| 组件内简单状态 | `useState` |
| 多状态联动/状态机 | `useReducer` |
| 请求/订阅等副作用 | `useEffect` |
| 需要在绘制前同步读写 DOM | `useLayoutEffect` |
| 保存不触发渲染的可变值 / DOM 引用 | `useRef` |
| 昂贵计算结果缓存 | `useMemo` |
| 稳定函数引用（配合 memo/依赖数组） | `useCallback` |
| 跨层级共享数据 | `useContext` |
| 暴露命令式方法给父组件 | `forwardRef` + `useImperativeHandle` |
| 高频输入/大列表不卡顿 | `useTransition` / `useDeferredValue` |
| 逻辑复用 | 自定义 Hook（`useXxx`） |

### 7.2 常见坑

- **`useEffect` 依赖数组漏写**：一律让 `eslint-plugin-react-hooks` 的 `exhaustive-deps` 通过。
- **直接 mutate state（数组 `push`/对象属性赋值）**：React 检测不到变化，必须返回新引用。
- **内联对象/函数作为 props 传给 `memo` 组件**：导致 memo 失效，需要 `useMemo`/`useCallback` 包裹。
- **在条件/循环里调用 Hook**：违反 Hooks 规则，导致状态错位，React 会直接报错。
- **把所有状态都塞进一个大 Context 的 value**：任意字段变化都会导致所有消费者重渲染，应拆分 Context 或做好 `useMemo`。
- **异步回调里直接用闭包中的旧 state**：优先用函数式更新 `setState(prev => ...)`。

### 7.3 TypeScript 常用写法

```tsx
// 组件 Props
interface Props {
  title: string;
  onClose?: () => void;
  children?: React.ReactNode;
}
const Foo = ({ title, onClose, children }: Props) => { ... };

// useState 显式泛型（初始值无法推断类型时）
const [list, setList] = useState<ProductCategory[]>([]);
const [current, setCurrent] = useState<ProductCategory | null>(null);

// useRef DOM

// forwardRef 组件
```

## 附：与 Vue 心智模型的关键差异（简要）

- React 是"重新调用整个函数渲染"，Vue 是"细粒度依赖追踪、按需更新"——所以 React 更依赖开发者手动控制"要不要重新计算/渲染"（`useMemo`/`memo`），而不是框架自动追踪。
- React state 必须不可变更新；Vue `reactive` 可以直接修改属性。
- React 没有内置的响应式"计算属性"，`useMemo` 只是渲染期间的缓存，不是持久的响应式派生值。

# 课外06：类型系统、包与模块、内存管理

[课外05](课外05-程序执行过程与解释型语言.md)讨论代码怎样被处理和执行。这篇继续回答三个问题：

| 主题 | 要解决的问题 |
| --- | --- |
| 类型系统 | 某个值能参与哪些操作？错误什么时候被发现？ |
| 包与模块 | 代码怎样组织？怎样找到并使用其他代码？ |
| 内存管理 | 对象在哪里存活？不用后怎样回收？ |

主要用 Java 和 JavaScript 对照，必要时补充 Python。以下没有标为“完整示例”的代码块，都是用于比较概念的片段；Java 语句片段默认放在方法内。

## 1. 类型系统：规定值可以怎样使用

### 1.1 类型是什么？

**类型描述一类值，以及对这些值允许进行的操作。**

例如，数字可以进行数值计算，字符串可以读取长度；但不能因为一个值叫 `user`，就认定它一定有 `name` 属性。

类型系统是语言中围绕这些规则建立的一套机制。它不只是“变量前面有没有写 `int`”。

### 1.2 静态类型和动态类型，主要区别在哪里？

Java 是静态类型语言。变量和表达式的类型在编译时确定，许多不合法的组合在编译时就会被拒绝。

```java
int age = 18;
age = "十八"; // 编译错误：String 不能赋给 int
```

JavaScript 是动态类型语言。同一个变量可以先持有数值，之后再持有字符串：

```javascript
let age = 18;
age = "十八"; // 合法
```

Python 也允许类似的重新绑定：

```python
age = 18
age = "十八"
```

这里变化的是变量当前关联的值，**不是原来的数字 18 被修改成了字符串对象**。

动态类型也有类型限制。例如，Python 执行 `1 + "2"` 会抛出 `TypeError`，不会因为没有声明变量类型就接受所有操作。

| 对比点 | Java | JavaScript / Python |
| --- | --- | --- |
| 变量有没有编译时确定的类型约束 | 有 | 普通变量不具有 Java 这种固定的静态类型约束 |
| 值有没有类型 | 有 | 也有 |
| 很多操作是否允许，何时判断 | 编译时会检查很多规则，运行时仍有检查 | 很多判断依赖运行时的实际值 |
| 是否可能运行时报错 | 会 | 会 |

Java 的静态检查不能提前知道一切。例如 `String name = null;` 可以通过编译，但执行 `name.length()` 仍会报错。静态类型也不表示一个变量只能引用某一个具体类：声明为接口或父类的变量，可以引用符合该类型约束的不同对象。[Java 17 类型与变量规范](https://docs.oracle.com/javase/specs/jls/se17/html/jls-4.html)

### 1.3 Java 的 var，是不是变成了动态类型？

不是。`var` 是**让编译器推断局部变量类型**。它从 Java 10 开始提供，在 Java 17 中可以使用。

```java
var age = 18;  // 编译器推断 age 的类型是 int
age = 19;     // 合法
age = "十八"; // 编译错误
```

对这个例子而言，写 `var age = 18;` 和 `int age = 18;` 得到的变量类型相同。

它与 JavaScript 的 `let` 解决的问题不同：

| 写法 | 这里的含义 |
| --- | --- |
| Java：`var age = 18;` | 类型由编译器推断，推断后仍受该类型约束 |
| JS：`let age = 18;` | 声明可以重新赋值的变量，不把它限制为 number |
| JS：`const age = 18;` | 不允许重新给变量赋值，不代表建立了 Java 式静态类型系统 |

同样，Java 的 `var` 不意味着“不可重新赋值”；是否限制重新赋值，要看 `final` 等规则。

### 1.4 TypeScript 的检查发生在哪里？

TypeScript 为 JavaScript 增加了静态类型检查：

```typescript
let age = 18;
age = "十八"; // TypeScript 类型检查报错
```

这里即使没写 `: number`，TypeScript 也可以推断类型。

但普通类型声明、接口和类型断言不会作为运行时校验规则保留到生成的 JavaScript 中。**声明“这是 User”，不等于已经验证服务器返回的 JSON 真符合 User。**

实际开发要区分：

- 静态检查：检查你写的代码如何使用数据。
- 运行时校验：检查此刻真正收到的数据，例如年龄是否为数字、必填字段是否存在。

外部接口响应、表单输入、配置文件等，仍可能需要运行时校验。[TypeScript 官方说明：类型擦除与静态检查](https://www.typescriptlang.org/docs/handbook/2/basic-types.html)

### 1.5 强类型、弱类型，和前面的分类是什么关系？

“强类型、弱类型”在不同资料里的判定标准并不统一，经常涉及隐式转换是否宽松。入门时，先看具体规则，不要用一个标签推导所有行为。

例如：

| 表达式 | 结果 |
| --- | --- |
| Java：`1 + "2"` | 字符串 `"12"` |
| JavaScript：`1 + "2"` | 字符串 `"12"` |
| Python：`1 + "2"` | 抛出 `TypeError` |

Java 有字符串拼接规则，并不因此变成动态类型语言。

还要把两个维度分开：

```text
静态 / 动态类型：类型规则怎样建立、怎样检查？
编译 / 解释执行：代码经过怎样的转换、怎样被执行？
```

JS 引擎可以进行 JIT 编译，但 JavaScript 仍是动态类型语言。

## 2. 包与模块：组织代码，并找到需要的代码

### 2.1 Java 的 package，不是磁盘绝对路径

假设你看到：

```text
src/main/java/com/example/demo/service/UserServiceImpl.java
```

文件顶部写着：

```java
package com.example.demo.service;
```

可以拆开理解：

| 内容 | 含义 |
| --- | --- |
| `src/main/java` | Maven 项目的主源码目录 |
| `com.example.demo.service` | Java 包名，用来组织类型、区分名称 |
| `UserServiceImpl` | 类的简单名称 |
| `com.example.demo.service.UserServiceImpl` | 类的全限定名，包含包名 |

在常规 Java 项目中，包名中的点对应源码目录下的层级。因此源码文件放在 `com/example/demo/service` 中。

**把整个项目从 D 盘移动到 E 盘，通常不需要修改 package。** 包名不是 `D:/...` 这样的本机路径。

使用不同包，可以存在两个简单名称都叫 `User` 的类，例如 `com.example.account.User` 与 `com.example.audit.User`。它们的完整名称不同，因此不是同一个类型。[Java 包与导入规范](https://docs.oracle.com/javase/specs/jls/se17/html/jls-7.html)

### 2.2 Java 的 import、依赖和 classpath，各管什么？

| 概念 | 解决什么问题 | 例子 |
| --- | --- | --- |
| Dependency，依赖 | 项目需要哪些外部库 | 在 POM 中声明 `spring-context` |
| Classpath，类路径 | 编译器或运行环境去哪里查找类 | 项目的编译输出目录、依赖 JAR |
| `import`，导入声明 | 当前源文件怎样用简单名称引用其他包的类型或静态成员 | `import java.util.List;` |

**Java 的 import 不负责下载库，也不是一条“马上执行被导入类”的指令。**

下面这行声明：

```java
import java.util.List;
```

主要是让你在当前文件中使用 `List` 这个简单名称。如果不导入，也可以在使用处写完整名称，例如：

```java
java.util.List<String> names = java.util.List.of("Java", "JavaScript");
```

在 Maven 项目中，Maven/IDE 根据依赖配置获得所需库，并为编译或运行准备相应的查找路径。仅仅在本地 `.m2` 仓库里有一个 JAR，不代表任何手写的 `java` 命令都能自动找到它。

同样，编译时找到类，不保证运行时一定找到类：两次使用的 classpath 可能不同。这也是“编译成功，运行时报找不到类”的一种原因。

### 2.3 用一个小例子把包名和运行命令连起来

下面是完整示例，不需要 Maven，也没有第三方依赖。

手动建立目录和文件：

```text
package-demo/
└── src/
    └── com/
        └── example/
            └── demo/
                └── PackageHello.java
```

`PackageHello.java`：

```java
package com.example.demo;

import java.util.List;

public class PackageHello {
    public static void main(String[] args) {
        List<String> names = List.of("Java", "JavaScript");
        System.out.println(names);
    }
}
```

使用 JDK 17，在 **`package-demo` 目录**中执行：

```powershell
javac -encoding UTF-8 -d out src/com/example/demo/PackageHello.java
java -cp out com.example.demo.PackageHello
```

输出：

```text
[Java, JavaScript]
```

`-d out` 指定编译输出目录，编译器会在它下面生成：

```text
out/com/example/demo/PackageHello.class
```

运行时：

- `-cp out` 指向包目录层级的根，而不是直接指向 `out/com/example/demo`。
- `com.example.demo.PackageHello` 是完整类名，不写 `.class` 后缀。

这个例子中没有第三方 JAR；`List` 来自 Java 标准库。

### 2.4 JavaScript、Python 的 import，为什么感觉不一样？

JS 的 ES 模块除了提供导出的名称，还参与模块的加载、链接和求值。**模块求值会执行它的顶层代码**。

用 Node.js 做一个完整小实验。为了明确使用 ES 模块，把两个文件保存为 `.mjs`，放在同一目录。

`user.mjs`：

```javascript
console.log("user 模块执行了");

export const name = "Yang";
```

`app.mjs`：

```javascript
import { name } from "./user.mjs";

console.log(name);
```

到这两个文件所在的目录执行：

```powershell
node app.mjs
```

输出：

```text
user 模块执行了
Yang
```

在这个没有循环依赖的简单例子中，依赖模块先求值，随后执行入口模块的顶层代码。同一模块通常会被缓存，不是每个文件导入它都重新执行一遍。[Node.js ES 模块说明](https://nodejs.org/api/esm.html)

Python 第一次导入一个普通模块时，通常也会执行模块顶层代码，后续在同一进程中再次导入通常会利用缓存。例如 `import user` 可能执行 `user.py` 里的顶层 `print`。[Python 模块说明](https://docs.python.org/3/tutorial/modules.html)

所以，不能只因为三种语言都有 `import`，就认为它们执行了完全相同的操作。

### 2.5 package、module、JAR，不是一对一对应

| 名称 | 在对应语境中通常指什么 |
| --- | --- |
| Java package | 组织类和接口的命名空间 |
| JAR | Java 的归档格式，一个 JAR 可以包含多个包的类和资源 |
| Maven module | 多模块项目中的子项目，通常有自己的 POM |
| Java 模块（JPMS） | Java 9 引入的模块系统中的单位，可用 `module-info.java` 声明依赖与导出 |
| JavaScript ES module | 按模块规则组织并执行的代码单位，使用 `export` 和 `import` |
| npm package | npm 安装和发布的单位，一个包可以包含多个 JS 模块 |
| Python module | 一个可导入的模块，常见形式是一个 `.py` 文件 |
| Python package | 用于组织子模块的包，常规包通常是带 `__init__.py` 的目录 |

Python 还有不要求 `__init__.py` 的命名空间包，暂时知道存在即可。

现在学习 Maven/Spring 时，优先分清 **Java 包、Maven 依赖、classpath**。看到“模块”先判断上下文，不需要为了建立这些概念立即改造项目使用 JPMS。

## 3. 内存管理：调用结束，不代表对象立即消失

### 3.1 先区分“调用记录”和“对象”

以 Java 为例，先建立两个概念：

| 名称 | 入门时怎样理解 |
| --- | --- |
| Stack，栈 | 保存当前线程的方法调用状态 |
| Stack Frame，栈帧 | 某一次方法调用的记录，包含局部变量等执行所需信息 |
| Heap，堆 | JVM 中为对象和数组分配内存的区域 |

方法被调用时创建相应栈帧，调用完成后移除；对象能否继续存活，要看它是否仍能被程序访问到，而不只看创建它的方法是否结束。[JVM 运行时数据区](https://docs.oracle.com/javase/specs/jvms/se17/html/jvms-2.html#jvms-2.5)

下面是完整示例，保存为 **`MemoryDemo.java`**，不添加 `package` 声明：

```java
public class MemoryDemo {
    static String[] createNames() {
        String[] names = new String[]{"Java", "JavaScript"};
        return names;
    }

    public static void main(String[] args) {
        String[] result = createNames();
        System.out.println(result[0]);
    }
}
```

在文件所在目录执行：

```powershell
javac -encoding UTF-8 MemoryDemo.java
java -cp . MemoryDemo
```

输出 `Java`。原因是：

```text
createNames 执行时：
局部变量 names ──引用──> 数组对象

createNames 返回后：
main 中的 result ──引用──> 同一个数组对象
```

返回的是数组的引用，数组仍然可用。调用记录结束了，不等于返回对象也被销毁了。

这是 JVM 的逻辑模型，具体实现可能优化内存分配。不要机械地记成“所有基本类型都在栈上”：例如对象中的 `int` 字段就是对象数据的一部分。

### 3.2 垃圾回收怎样知道哪些对象可以回收？

**GC（Garbage Collection，垃圾回收）**负责自动回收符合条件的对象内存。

对 Java、常见 JS 引擎，入门可以先理解“可达性”：

> 从仍在使用的程序状态出发，沿着引用关系，还能不能找到这个对象？

如果已经找不到，对象才可能成为回收对象；何时真正回收，由运行环境决定。

看 JavaScript 片段：

```javascript
let user = { name: "Yang" };
let selectedUser = user;

user = null;

console.log(selectedUser.name); // Yang
```

`user = null` 只断开了一个引用。另一个变量仍然指向同一个对象，所以对象仍然可达。

即使最后一个有效引用也消失，**也不等于此刻必定立即回收**。不要把 `null` 当成“执行释放内存”的命令。

不同实现的回收机制可以不同。比如 CPython 主要使用引用计数，并辅以循环垃圾回收；不能把它的具体回收时机直接套到 JVM 或 JS 引擎上。[Python 对象与回收说明](https://docs.python.org/3/reference/datamodel.html#objects-values-and-types)

### 3.3 有 GC，为什么还会内存泄漏？闭包是不是泄漏？

自动回收也需要知道对象是否仍被引用。**业务已经不需要，但代码仍长期保留引用的数据，可能一直无法释放。**

例如，下面是一个用于观察原因的 JS 反例：

```javascript
const history = [];

function remember(payload) {
    history.push(payload);
}
```

如果这个数组长期可达、`remember` 持续加入大量数据，而业务又没有需要它们的理由或清理策略，内存就可能持续增长。

GC 能判断“还能不能找到这些数据”，不能替你判断“业务上是不是早就不需要了”。

Java 中长期保留的集合、没有淘汰机制的缓存，也可能出现类似问题。

闭包本身则不是内存泄漏。下面的状态保留就是正常需求：

```javascript
function createCounter() {
    let count = 0;
    return () => ++count;
}

const next = createCounter();
console.log(next()); // 1
console.log(next()); // 2
```

`createCounter` 调用已经结束，但返回的函数仍然需要访问 `count`，因此相关状态会被保留。不要理解为“函数返回后，一切局部状态都必须消失”。

需要检查的是：闭包或监听器是否被保留过久，从而连带保留了大量已经不用的数据。

### 3.4 GC 和关闭文件、连接，不是一件事

| 管理对象 | 需要做的事情 |
| --- | --- |
| Java/JS 对象占用的内存 | 由 GC 按其机制回收 |
| 文件、网络连接等外部资源 | 按资源 API 及时关闭或释放 |
| 定时器、事件订阅 | 不再需要时取消，避免继续执行或保留引用 |
| Spring 管理的资源 | 结合容器和 Bean 的生命周期执行清理 |

文件对象除了占用内存，还可能对应操作系统的文件句柄；数据库连接也可能占用服务端资源。不能仅靠“这个对象以后会被 GC”保证这些资源及时释放。

Java 常用 **try-with-resources**：资源成功打开后，在代码块正常结束或抛出异常离开时调用 `close()`。资源类型需要支持 `AutoCloseable` 等相应接口。[Java 自动关闭资源说明](https://docs.oracle.com/javase/tutorial/essential/exceptions/tryResourceClose.html)

下面是用法片段，需要放进方法中，并导入相应类型或像这里使用完整名称。假设当前工作目录存在 UTF-8 编码的 `notes.txt`，所在方法还需要处理或声明 `IOException`：

```java
try (java.io.BufferedReader reader = java.nio.file.Files.newBufferedReader(
        java.nio.file.Path.of("notes.txt"),
        java.nio.charset.StandardCharsets.UTF_8)) {
    System.out.println(reader.readLine());
}
```

这里关注的是代码块结束时及时关闭 `reader`；对象的内存什么时候被 GC，是另一个问题。

你熟悉的语言中也有对应的资源管理做法：

| 场景 | 常见做法 |
| --- | --- |
| Python 打开文件 | `with open(...) as file:` |
| JS 周期定时器 | 不再需要时 `clearInterval(timerId)` |
| 浏览器 DOM 事件 | 按需要 `removeEventListener(...)` |
| Java 需要关闭的资源 | `try-with-resources` 或按 API 明确关闭 |
| Spring 独立创建的应用上下文 | 使用结束后 `context.close()` 等方式关闭 |

Spring 容器关闭可以触发它所管理的销毁回调，这与 JVM 的垃圾回收不同；也不是所有作用域的 Bean 都由容器自动完成销毁，例如 prototype Bean 需要额外考虑清理责任。

## 4. 把三个主题放回你正在学的 Spring 项目

假设代码里有 `UserServiceImpl` 调用 `UserDaoImpl` 查询数据：

| 看到的现象 | 对应哪个概念 |
| --- | --- |
| 方法声明返回 `List<User>`，却返回不兼容类型 | 类型系统与编译时检查 |
| 源码中写 `package com.example.demo.service;` | Java 包与名称组织 |
| `import org.springframework...` 无法解析 | 先检查依赖是否可用、项目是否正确导入 |
| 编译通过，运行却找不到某个第三方类 | 检查运行时 classpath、依赖和打包结果 |
| Service 把历史查询结果不断塞进长期保留的集合 | 内存占用与引用保留 |
| 查完数据后连接没有按约定释放 | 资源管理，不能指望 GC 及时兜底 |

这些概念会贯穿后续课程。遇到问题时，先判断是在检查类型、查找代码，还是管理对象与资源，再选择对应的排查方向。

## Java 语言与运行环境

| 英文术语 | 全称 / 中文 | 解决什么问题与例子 |
| --- | --- | --- |
| Annotation | 注解 | 附在类、字段或方法等位置的信息，由编译器或工具等处理，自己不是业务执行逻辑 |
| Bytecode | 字节码 | Java 编译后的指令形式，通常存于 `.class` 文件 |
| Classpath | 类路径 | 运行时等场景查找类与资源的位置；`java -cp out Demo` 中 out 就是其中一个位置 |
| Compile | 编译 | 将源码转换为目标代码。例如 javac 将 Java 源码编译为字节码 |
| Getter | 属性读取方法 | 读取对象中的值。例如 getName()；record 的 name() 也承担读取作用 |
| Instrumentation | 插桩 | 对字节码进行增强或修改。例如监控工具在方法中加入耗时采集逻辑 |
| JAR | Java Archive，Java 归档文件 | 打包类和资源的文件；不是所有 JAR 都能直接 `java -jar` 运行 |
| JDK | Java Development Kit，Java 开发工具包 | 提供编译、运行等工具；写 Java 程序时安装它 |
| JRE | Java Runtime Environment，Java 运行环境 | 运行 Java 所需的环境概念；现代 JDK 的安装布局不一定有独立 jre 目录 |
| JVM | Java Virtual Machine，Java 虚拟机 | 执行 Java 字节码的运行基础 |
| LTS | Long-Term Support，长期支持 | 厂商为选定版本提供较长维护周期；具体承诺取决于发行商 |
| Package | 包 | Java 类型的命名空间，例如 `com.example.product`；不等于压缩包 |
| record | 记录类（Java 16 正式引入） | 简化数据载体定义，自动提供组件访问方法等。例如 record Product(String name) 自动提供 name() |
| Reflection | 反射 | 运行时查看类型、读取字段或调用方法的一组能力 |
| Runtime | 运行时 | 程序实际执行的阶段。例如应用启动或处理请求时发生的异常称为运行时发生的异常 |
| Setter | 属性设置方法 | 修改对象中的值。例如 setName("产品A")；record 不自动提供 setter |

| POM | Project Object Model，项目对象模型 | Maven 项目信息与构建配置，通常写在 pom.xml 中 |

## Spring 框架、容器与配置

| 英文术语 | 全称 / 中文 | 解决什么问题与例子 |
| --- | --- | --- |
| ApplicationContext | 应用上下文 | Spring 常用的容器接口，支持对象管理、资源访问与事件发布。例如取得容器中的业务对象 |
| Auto-configuration | 自动配置 | 根据依赖、配置项及已有组件等条件提供配置。例如满足条件时配置 Web 请求处理组件 |
| Autowiring | 自动装配 | 由容器按类型等规则匹配并提供依赖。例如自动为构造器参数选择合适的 Bean |
| Bean / Beans | Spring 管理的对象 / 对象管理能力 | Bean 是交给 Spring 管理的对象，图中 Beans 指相关管理能力。例如创建 ProductService 并装配依赖 |
| BeanFactory | Bean 工厂接口 | 提供 Spring 对象管理的基础接口。例如按名称或类型获取 Bean |
| Component Scan | 组件扫描 | 在指定包范围内发现符合条件的组件并注册；不是扫描到的每个类都会变成 Bean |
| Context | 应用上下文 | 在对象管理基础上提供资源访问、事件等能力。例如通过 ApplicationContext 发布应用事件 |
| Core | 核心基础工具 | 提供框架所需的基础工具与抽象。例如用统一的资源访问接口读取配置文件 |
| Core Container | 核心容器 | Spring 管理对象及其依赖的核心能力。例如创建并连接 Service 与 Repository |
| DI | Dependency Injection / 依赖注入 | 从外部提供对象需要的依赖。例如通过 ProductService 的构造器传入 Repository |
| Externalized Configuration | 外部化配置 | 将配置与业务代码分离。例如在 application.yml 或环境变量中设置数据库地址 |
| IoC | Inversion of Control / 控制反转 | 将对象创建、组装等控制权交给容器。例如由 Spring 组织 Service 与 Repository |
| Lifecycle | 生命周期 | 对象从创建、初始化、使用到销毁的过程 |
| Profile | 配置分组标识 | 例如激活 dev，选择相应配置或 Bean；它不等于操作系统环境变量 |
| Property | 属性 | 对象语境中表示数据属性，如产品名称；配置语境中表示配置项，如 server.port |
| Scope | 作用域 | 指定对象或依赖生效的范围：Bean Scope 控制实例共享方式；Maven dependency scope 控制库在哪些构建阶段可用 |
| SpEL | Spring Expression Language / Spring 表达式语言 | 在支持表达式的位置进行取值或计算。例如 `#{1 + 2}` 表示计算 1 加 2 |
| Spring Boot | Spring 应用开发框架 | 简化 Spring 应用的依赖配置与启动。例如快速搭建提供 HTTP 接口的应用 |
| Spring Framework | Spring 基础框架 | 提供对象管理、Web、事务等应用基础能力。例如管理业务对象及其依赖 |
| Starter / Starters | 起步依赖组合 | 集中引入某类功能的常用依赖。例如通过 Web Starter 引入 Web 开发依赖 |
| Wiring | 依赖装配 | 将协作对象连接起来。例如为 Service 提供 Repository |

## AOP 切面与代理

| --- | --- | --- |

| Proxy | 代理 | 调用先经过代理对象，由它安排增强逻辑和目标方法调用 |
| Target | 目标对象 | 真正实现业务逻辑的对象 |

## 业务分层与数据对象

| 英文术语 | 全称 / 中文 | 解决什么问题与例子 |
| --- | --- | --- |
| BO | Business Object，业务对象 | 表达业务处理中需要的数据，是否单独设一层取决于项目 |
| Controller | 控制器 | 接收 Web 请求，调用业务逻辑并返回结果 |
| Converter | 转换器 | 例如将 Entity 转成响应 DTO，去掉不应返回的内部字段 |
| DAO | Data Access Object，数据访问对象 | 负责数据访问的对象；与 Repository 的用词边界因架构而异 |
| DO | Data Object / 数据对象 | 项目中常用于命名数据库数据对象。例如 ProductDO 对应产品表数据；具体含义以项目约定为准 |
| DTO | Data Transfer Object，数据传输对象 | 在层或系统之间传递数据，例如创建产品的请求对象 |
| Entity | 实体 | 持久层常指与数据库映射的对象；领域建模中也有“以身份区分的实体”含义 |
| Mapper | 映射器 | MyBatis 中通常是数据库访问接口；其他库中也可能指对象转换器，要结合 import 和实现判断 |
| PO | Persistent Object / 持久化对象 | 表示用于持久化的数据对象。例如保存到数据库的 ProductPO；具体命名以项目约定为准 |
| POJO | Plain Old Java Object，普通 Java 对象 | 强调普通对象，不要求为某种框架继承特定基类 |
| Repository | 仓储 | 封装数据获取与保存，给业务提供访问数据的接口 |
| Service | 服务 / 业务层 | 处理业务规则，例如判断产品是否允许下架；不一定指独立部署的微服务 |
| VO | View Object / 视图对象；Value Object / 值对象 | 需按项目语境区分：视图对象为页面组织返回数据；领域值对象按属性值表达概念，如金额 |

## Web、接口与数据传输

| 英文术语 | 全称 / 中文 | 解决什么问题与例子 |
| --- | --- | --- |
| API | Application Programming Interface，应用程序编程接口 | 可供别的代码调用的约定；HTTP 接口是其中一种，Java 方法也可以属于某个 API |
| Client | 客户端 | 主动发起请求的一方。例如浏览器请求后端，或后端通过 HTTP 客户端调用第三方接口 |
| Deserialization | 反序列化 | 把 JSON 等表示转换回对象；不同于直接执行其中的文本 |
| Endpoint | 接口端点 | 可调用的具体入口，例如 `GET /products/101`；同一路径配不同 HTTP 方法可能是不同操作 |
| Filter | 过滤器；此处指 Servlet Filter | 在 Servlet 请求处理链上执行公共逻辑。例如包装请求或处理跨域响应头 |
| Interceptor | 拦截器；此处指 Spring MVC HandlerInterceptor | 在 MVC 处理器执行前后介入处理。例如记录 Controller 请求耗时 |
| JSON | JavaScript Object Notation | 文本数据交换格式，Java、Python 等同样可以处理 |
| OXM | Object/XML Mapping / 对象与 XML 映射 | 在 Java 对象与 XML 之间转换。例如将 XML 文档中的字段转换为对象属性 |
| Param | Parameter / 参数 | 传给操作的输入值。例如查询参数 page=1 |
| Payload | 有效载荷 | 消息或请求中实际传输的业务内容。例如创建产品的 JSON 请求体 |
| Portlet | 门户应用组件 | 旧式门户应用中用于构成页面局部内容的组件。例如门户中的公告窗口；作为历史术语查阅 |
| Request | 请求 | 调用方发起的操作及携带的数据。例如提交产品创建参数 |
| Response | 响应 | 被调用方返回的处理结果。例如返回新建产品的 ID |
| REST | Representational State Transfer，表述性状态转移 | 一种架构风格；不是“只要返回 JSON 就是 REST” |
| REST Clients | REST：Representational State Transfer / 表述性状态转移；此处指调用 HTTP 接口的客户端工具 | 让后端主动调用外部接口。例如用 RestClient 查询第三方产品信息 |
| Serialization | 序列化 | 把对象转换为可存储或传输的表示，例如响应对象转 JSON |
| Servlet | Java 服务端请求与响应处理规范/API | 约定服务端组件如何处理请求。例如 Tomcat 运行 Spring MVC 的 DispatcherServlet，由它分发请求 |
| Servlet Container | Servlet 容器 | 运行 Servlet 并管理请求处理及生命周期。例如 Tomcat |
| Spring MVC | Model-View-Controller / 模型—视图—控制器；此处指基于 Servlet 的 Spring Web 框架 | 处理 HTTP 请求、参数和响应。例如 Controller 接收产品查询请求并返回 JSON |
| Spring WebFlux | Spring 响应式 Web 框架 | 支持非阻塞请求处理和按消费能力调节数据流。例如以响应式方式持续返回数据 |
| Validation | 数据校验 | 检查输入是否符合约束。例如检查标题不能为空、价格不能为负 |
| Web | Web 应用相关能力 | 支持基于 HTTP 等协议的应用交互。例如接收网页提交的表单并返回响应 |
| WebSocket | 双向通信协议 | 允许连接双方主动发送消息。例如聊天室中服务端主动推送新消息 |

## 并发、任务与调用可靠性

| 英文术语 | 全称 / 中文 | 解决什么问题与例子 |
| --- | --- | --- |
| Asynchronous | 异步 | 发起操作后可以继续处理其他工作，稍后取得结果。例如提交任务后通过 Future 获取结果 |
| Backpressure | 背压 | 消费者向上游表达自己的接收能力，避免生产速度持续超过处理能力 |
| Blocking | 阻塞 | 当前线程在条件满足前等待。例如线程等待数据库返回结果 |
| Concurrency | 并发 | 多个任务在同一段时间内推进。例如一个线程轮流处理多个任务 |
| Idempotency | 幂等性 | 同一操作重复执行后，预期业务效果与执行一次一致；例如同一支付单避免重复扣款，不要求每次响应完全相同 |
| Non-blocking | 非阻塞 | 操作无法立即完成时不将当前线程挂起等待结果。例如由事件通知数据已可读取 |
| Parallelism | 并行 | 多个任务在同一时刻执行。例如多个 CPU 核心同时进行计算 |
| Reactive | 响应式 | 围绕数据流及其变化组织处理；不是前端 Vue 响应式机制的直接同义词，也不是“写了回调就算” |
| Retry | 重试 | 失败后再次尝试；要结合幂等性，避免重复扣款等副作用 |
| Synchronous | 同步 | 调用流程等待操作完成后再继续。例如调用查询方法并直接取得结果 |
| Tasks & Scheduling | 任务执行与调度 | 安排任务的执行方式和触发时间。例如交给线程池执行任务，或每天定时清理过期记录 |
| Thread Pool | 线程池 | 复用工作线程执行任务；不是线程越多性能越好 |
| Timeout | 超时 | 等待超过设定期限后结束等待或报告失败；不保证对方已经停止处理 |

## 测试、调试与部署监控

| 英文术语 | 全称 / 中文 | 解决什么问题与例子 |
| --- | --- | --- |
| Actuator | 应用监控与管理功能 | 提供健康检查、指标等运行信息。例如通过健康端点检查应用状态 |
| Breakpoint | 断点 | 在指定位置或条件满足时暂停执行。例如暂停在价格计算方法中查看输入值 |
| CD | Continuous Delivery / 持续交付；Continuous Deployment / 持续部署 | 持续交付使通过验证的版本随时可发布；持续部署进一步自动发布到生产环境 |
| CI | Continuous Integration / 持续集成 | 频繁集成代码并自动验证。例如提交代码后自动构建和测试 |
| Debug | 调试 | 观察程序运行过程并定位问题。例如查看变量和调用栈 |
| Docker Container | Docker 容器 | 用于隔离并运行应用进程的环境，与 Spring 管理对象的容器不是同一种东西 |
| Integration Test | 集成测试 | 验证多个组件的配合。例如测试 Service 能否通过 Mapper 正确保存记录 |
| Log | 日志 | 记录具体事件及上下文。例如记录订单保存失败的原因 |
| Metric | 指标 | 以数值观察系统状态或趋势。例如请求数、错误率和响应耗时 |
| Stack Trace | 异常堆栈 | 显示异常相关的方法调用信息；不等于跨服务的分布式 Trace |
| Test | 测试支持 | 辅助验证代码及组件协作。例如配合 JUnit 验证价格计算，或加载 Spring 测试上下文验证 Service 与数据访问组件的集成 |
| Trace | 调用追踪 | 串联一次请求经过的调用过程。例如追踪订单请求如何调用库存服务 |
| Unit Test | 单元测试 | 验证一个较小代码单元的行为。例如测试价格计算方法是否正确 |

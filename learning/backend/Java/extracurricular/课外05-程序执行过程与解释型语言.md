# 课外05：程序执行过程与解释型语言

这篇接着[课外04：Maven、JVM 与 Spring 生命周期](课外04-Maven、JVM与Spring生命周期.md)，把视角从工具和框架移到程序本身：**你写下的代码，经过哪些处理，最后才会产生结果？**

主要对照 Java 与 JavaScript，必要时补充 Python。Java 示例按 JDK 17 讲解；涉及引擎内部实现时，会明确说的是 HotSpot、V8 还是 CPython。

## 1. 程序执行过程，是不是“编译原理”？

有关系，但范围不完全相同。

**编译原理主要研究：如何理解源代码，并把它转换成另一种表示。** 例如，把 Java 源码转换为字节码，把某种中间表示转换为机器码。

一个程序真正运行起来，还需要找到依赖、准备内存、执行指令、处理输入输出、回收内存等。这些也涉及运行环境、虚拟机和操作系统。

| 你想了解的问题 | 主要涉及的内容 |
| --- | --- |
| 编译器怎么知道括号不匹配？ | 语法分析 |
| 为什么 Java 不能把字符串赋给 `int`？ | 类型系统、编译时检查 |
| `.java` 怎么变成 `.class`？ | 编译 |
| JVM 怎么找到并执行一个类？ | 类加载、链接、初始化、执行 |
| 对象不用后，内存谁来释放？ | 运行时内存管理 |
| 为什么控制台程序执行完就退出？ | 程序入口、线程、进程退出 |

所以，可以学习一套通用的“程序处理与执行”概念，但**不同语言、实现和运行方式，不一定经过完全相同的阶段**。

“没有统一的 Java 项目生命周期”也不等于“Java 执行过程没有规范”：Java 对类加载、初始化等有明确规范，只是不能把 Maven、JVM、Spring 的阶段混成一张统一流程表。

## 2. 先认识代码的三种表示

### 2.1 源代码、字节码和机器码

| 名称 | 是什么 | 例子 |
| --- | --- | --- |
| Source Code，源代码 | 人用编程语言编写的代码 | `Hello.java`、`app.js`、`app.py` |
| Bytecode，字节码 | 供某种虚拟机或引擎处理的指令表示 | Java 的 `.class` 中包含 JVM 字节码 |
| Machine Code，机器码 | 某种 CPU 指令集对应的指令编码 | 面向 x86-64 或 ARM64 的机器指令 |

可以这样理解：

```text
源代码：方便人表达逻辑
字节码：方便特定虚拟机或引擎处理
机器码：CPU 实际执行的指令
```

**字节码不是所有语言通用的一种格式。** JVM、V8、CPython 的字节码各有自己的规则，不能因为都叫字节码，就互相拿来执行。

解释执行时，CPU 仍然在执行机器指令——执行的是解释器自身的机器代码，由解释器按照被解释代码的要求完成工作。

### 2.2 “编译”不一定意味着生成机器码

编译可以把代码转换成不同目标：

```text
Java 源码         → JVM 字节码
TypeScript 源码   → JavaScript
运行中的热点代码 → 机器码
```

因此，“这个程序经过编译”和“这个程序已经是原生可执行文件”，不是同一个意思。

## 3. 编译器通常要理解哪些东西？

以 Java 的一行代码为例：

```java
int total = price + 1;
```

这里假设 `price` 已声明为 `int`。下面是便于理解的常见处理任务，不要求每个编译器严格分成这些独立步骤。

| 任务 | 通俗解释 | 对这行代码做什么 |
| --- | --- | --- |
| Lexical Analysis，词法分析 | 分辨一个个有意义的符号 | 识别 `int`、`total`、`=`、`price`、`+`、`1`、`;` |
| Parsing，语法分析 | 判断这些符号能否组成合法句子 | 判断这是一条变量声明，并识别加法表达式 |
| Semantic Analysis，语义分析 | 检查名称和操作的含义是否符合规则 | 检查 `price` 是否存在、类型能否相加、结果能否赋给 `int` |
| Optimization，优化 | 在保持规定行为的前提下改进实现 | 某些可以提前确定的计算可能被简化 |
| Code Generation，代码生成 | 生成目标表示 | `javac` 生成 JVM 可处理的类文件 |

**AST（Abstract Syntax Tree，抽象语法树）** 是用树形结构表示代码关系的一种方式。比如 `price + 1` 可以表示为“加法”节点，下面有 `price` 和 `1` 两个子节点。

它表示“代码结构是什么”，还不是最终执行结果。

JavaScript 也要进行语法分析，但不能照搬 Java 的全部静态类型检查规则。**动态类型不等于没有语法规则，也不等于不用解析代码。**

## 4. Java：从源码到运行结果

### 4.1 亲自区分“编译”和“运行”

新建文件，文件名必须是 **`Hello.java`**，内容如下。这是完整示例，没有 `package` 声明。

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
```

在 VSCode 中打开它所在的文件夹，再打开终端。确认当前目录能看到 `Hello.java` 后执行：

```powershell
javac -encoding UTF-8 Hello.java
java -cp . Hello
```

| 命令 | 做了什么 | 能观察到什么 |
| --- | --- | --- |
| `javac -encoding UTF-8 Hello.java` | 编译源文件 | 成功后生成 `Hello.class`，此时不会输出 `Hello` |
| `java -cp . Hello` | 启动 JVM，运行主类 | 执行 `main`，输出 `Hello` |

`-cp .` 表示把当前目录作为查找类的位置；最后的 `Hello` 是类名，**不要写成 `Hello.class`**。如果提示“找不到文件”，先检查终端当前目录和实际文件名。[javac 官方说明](https://docs.oracle.com/en/java/javase/17/docs/specs/man/javac.html)

### 4.2 JVM 开始运行后，还要做什么？

对这个简单示例，可以这样看：

```text
Hello.java
    │ javac 编译
    ▼
Hello.class
    │ java 启动 JVM
    ▼
加载主类 → 链接主类 → 初始化主类 → 执行 main
```

- **加载（Loading）**：找到类的二进制表示，让 JVM 认识这个类。
- **链接（Linking）**：进行验证、准备等处理，并按需要解析对其他类、字段、方法的引用。
- **类初始化（Initialization）**：执行需要执行的静态字段初始化和静态代码块。
- **执行（Execution）**：执行方法中的指令，例如输出文字。

这不是说“程序所有类必须先全部初始化，再进入 `main`”。其他类可以在后续使用时才加载、初始化；引用解析的时机也允许一定灵活性。[Java 17 执行规范](https://docs.oracle.com/javase/specs/jls/se17/html/jls-12.html)

### 4.3 Java 运行时为什么还会出现“编译”？

因为两次编译处理的对象和时机不同：

| 编译 | 什么时候发生 | 主要做什么 |
| --- | --- | --- |
| `javac` 源码编译 | 通常在运行应用前 | Java 源码 → JVM 字节码 |
| JIT（Just-In-Time，即时编译） | 应用运行过程中 | 把适合编译的代码转换成机器码 |

常见的 HotSpot JVM 可以解释执行字节码，也可以通过 JIT 编译提高执行效率。因此，**Java 常见执行方式结合了编译与解释**，并不是生成 `.class` 后就完全没有解释器参与。

这里介绍的是常见实现方式，不要求所有 JVM 都采用完全相同的策略。[HotSpot 的解释器与分层编译](https://docs.oracle.com/en/java/javase/17/vm/java-hotspot-virtual-machine-performance-enhancements.html)

## 5. JavaScript 和 Python：没有手动编译，也可能经过编译

### 5.1 JavaScript：区分项目构建和引擎执行

你熟悉的前端项目，往往有两层处理：

```text
项目工具这一层：
TypeScript / JSX / 多个源码文件
    → 类型检查、转换、打包等处理
    → 交给浏览器的 JavaScript

JavaScript 引擎这一层：
读取 JavaScript
    → 解析和生成内部表示
    → 执行代码，并可能进行机器码编译
```

第一层取决于项目配置：并非每个构建命令都做类型检查，也不是所有 JS 程序都需要打包。

第二层由引擎负责。以 V8 为例，它有 Ignition 字节码解释器，也有把代码编译为机器码的编译器。这里只画简化过程，不把某一版本的所有编译层级当成必须背诵的固定流程。[V8 Ignition](https://v8.dev/docs/ignition)、[V8 编译器示例：Sparkplug](https://v8.dev/blog/sparkplug)

所以，`npm run build` 里的构建处理，与浏览器运行 JS 时的引擎编译，是不同层次的事情。

直接运行下面这个文件同样可以。保存为 `hello.js`：

```javascript
console.log("Hello");
```

在安装了 Node.js 的环境中，到该文件所在目录执行：

```powershell
node hello.js
```

没有让你先手动执行编译命令，不代表引擎内部完全没有编译过程。

### 5.2 Python：解释器也可以先生成字节码

以常见的 **CPython** 实现为例，可以简化理解为：

```text
Python 源码 → 编译为字节码 → 解释器执行字节码
```

导入 Python 模块时，可能生成 `__pycache__` 中的 `.pyc` 字节码缓存，用于后续减少重复编译。这不等于生成了 CPU 直接运行的机器码，也不是每次运行入口脚本都一定会生成它。[Python 模块与字节码缓存](https://docs.python.org/3/tutorial/modules.html#compiled-python-files)

Python 是语言，CPython 是它的一种实现。其他实现可以采用不同的执行策略，例如使用 JIT。

## 6. 为什么 JS、Python 仍常被叫作“解释型语言”？

**这是对传统使用方式和常见执行方式的概括，不是“内部禁止出现编译器”的规定。**

从开发者平时交给运行环境的东西看，差异比较容易理解：

| 常见使用方式 | 交给执行环境的内容 |
| --- | --- |
| Java：先编译，再用 JVM 运行 | 通常是 `.class` 或包含类文件的 JAR |
| JavaScript：浏览器加载 JS，或 `node app.js` | 通常是 JavaScript 代码 |
| Python：`python app.py` | 通常是 Python 源代码，由运行环境完成后续处理 |

这些都是常见方式，并不排除其他运行或发布方式。

**解释执行**的关键是：由解释器读取某种程序表示，并按照它的含义完成操作。这种表示可以是字节码，不一定是源码的一行文字。

因此，以下三句话可以同时成立：

- Python 通常被称为解释型语言。
- CPython 会先把源码编译为字节码。
- CPython 可以用解释器执行这些字节码。

Python 官方术语表本身也同时介绍了“解释型”和“字节码”，二者并不矛盾。[Python：interpreted](https://docs.python.org/3/glossary.html#term-interpreted)、[Python：bytecode](https://docs.python.org/3/glossary.html#term-bytecode)

学习时，最好把问题问具体：

> 这个实现，把什么代码转换成什么？什么时候转换？由谁执行？

这比只记“Java 是编译型，JS 是解释型”更能解释实际现象。

## 7. 编译期、运行时等词，怎样放到同一张图里？

### 7.1 常见阶段名词

| 术语 | 关注什么 | 例子 |
| --- | --- | --- |
| Build Time，构建期 | 项目产物怎样生成 | Maven 编译、测试、打包 |
| Compile Time，编译期 | 某次编译正在进行 | `javac` 检查类型并生成类文件 |
| Parse Time，解析时 | 当前代码的语法结构怎样被识别 | JS 引擎发现少了括号 |
| Load Time，加载时 | 所需代码怎样进入运行环境 | JVM 加载一个类 |
| Linking，链接 | 引用怎样连接到相应定义；具体含义依环境而定 | JVM 处理对其他类、方法的引用 |
| Initialization，初始化 | 使用前需要建立什么状态 | 执行 Java 类的静态初始化 |
| Startup，启动阶段 | 程序怎样准备好开始工作 | 启动 JVM、创建 Spring 容器 |
| Run Time / Runtime，运行时 | 程序正在被执行 | 初始化、调用方法、处理请求、运行 JIT |
| Shutdown，关闭阶段 | 程序怎样停止并清理资源 | 关闭连接、停止线程 |

**这些词不是一组互不重叠的格子。** 以一个 Java 服务为例：

```text
构建应用：编译源码 → 执行测试 → 打包

运行应用：启动与初始化 → 持续处理业务 → 正常关闭
          └──────── 都属于运行时 ────────┘
```

构建中的测试也需要执行代码，所以“处于构建流程”与“测试代码正在运行”可以同时成立。

“编译期错误”在普通 Java 讨论中通常指源码编译时发现的错误；但“发生在运行时的 JIT 编译”也是编译。要看说话者在讨论哪一层。

### 7.2 AOT、JIT 和 Runtime 的另一个意思

- **AOT（Ahead-Of-Time，提前编译）**：在目标程序运行前完成相关编译。讨论原生应用时，常指提前生成机器码；看到 AOT，要确认上下文中的编译目标。
- **JIT（Just-In-Time，即时编译）**：程序运行期间进行编译，常结合实际运行情况生成机器码。
- **Runtime 也可以指“运行环境”**：例如 JavaScript runtime，可能是在说执行 JS 所需的引擎和宿主能力，不是在说某个时间阶段。

### 7.3 与课外04里的 Maven 命令对照

`java -cp . Hello` 会启动 JVM 来执行主类；而 `mvn exec:java` 的 `java` 目标是在 **Maven 所在的 JVM 内**运行指定主类。

所以 `mvn compile exec:java` 不能理解为“编译之前没有 JVM，之后才启动 JVM”：Maven 本身就是 Java 程序，执行 Maven 时 JVM 已经在工作。[exec:java 官方说明](https://www.mojohaus.org/exec-maven-plugin/java-mojo.html)

## 8. 用报错判断：出问题的是哪种处理？

以下 Java 片段假设写在 `main` 中，都是用于说明错误的反例，不要合在一起当作正常示例运行。

```java
int age = "十八"; // 源码编译时：字符串不能赋给 int
```

```java
String name = null;
System.out.println(name.length()); // 可以编译，执行到这里会抛出 NullPointerException
```

JavaScript 也能区分语法问题和执行问题：

```javascript
const age = ; // 语法解析失败：等号右侧缺少表达式
```

```javascript
const user = null;
console.log(user.name); // 执行时：不能读取 null 的属性，抛出 TypeError
```

虽然你可能都是点击“运行”后才看到报错，但第一次可能还在解析代码，第二次才是在执行表达式。**按下运行按钮的时间，不能代替对错误阶段的判断。**

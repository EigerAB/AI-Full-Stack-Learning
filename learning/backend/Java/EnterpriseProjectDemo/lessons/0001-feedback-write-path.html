写入链路：一次点踩如何落库

目标：能把 PUT /chat/messages/runs/{runId}/feedback 到表 FM_SQUARE_CHAT_FEEDBACK 的每一层代码指出来，并说清每层只管什么。

一、先建立地图：四层各司其职

浏览器（aichat） 用户点「踩」，前端调 PUT /gmp/agent-platform/chat/messages/runs/{runId}/feedback， body 是 {feedback, problemTypes, note}

↓ Spring Cloud Gateway 按 /chat/** 路由 + 注入可信身份头

Controller（协议层） 解析 HTTP → 校验参数 → 调 Service → 包装返回值。 不写业务逻辑

↓

Service（业务层） 编排业务规则：幂等、加锁、校验、决定写什么。 不写 SQL 细节，靠 Mapper

↓

Mapper（持久层） MyBatis-Plus 接口，把方法调用翻译成 SQL。 不知道"为什么查"，只知道"怎么查"

↓

达梦 DM8 表 FM_SQUARE_CHAT_FEEDBACK

记住一句话：Controller 管协议、Service 管业务、Mapper 管 SQL。读任何后端代码先用这把刀切。

二、Controller：薄得像纸

smart-square-chat/.../controller/ChatMessageController.java
@PutMapping("/runs/{runId}/feedback")
public AguiChatMessageFeedbackResult updateFeedback(
        @PathVariable String runId,
        @Valid @RequestBody AguiUpdateChatMessageFeedbackParam param) {
    return feedbackService.updateFeedback(runId, param);
}

三件事：@PutMapping 把 URL 绑到方法、@PathVariable/@RequestBody 取出参数、 @Valid 触发参数校验。然后立刻把活交给 Service。判断标准：Controller 里如果出现 if/else 业务判断，就是写错层了。

三、Service：全部业务都在这

smart-square-chat/.../service/chat/ChatMessageFeedbackService.java

updateFeedback() 方法上挂着 @Transactional——整个方法要么全成功、要么全回滚。 内部依次做了四件事：

  1. 解析与校验：parseFeedback 只认 good/bad； validateCombination 规定好评不能带问题类型。
  2. 幂等检查 isSubmittedFeedback：先按 org + userId + runId 查表——如果已提交过一模一样的值，直接返回成功（网络重试安全）； 如果已提交但值不同，抛「反馈已提交，不支持修改或清除」。
  3. 会话行锁：findBySessionIdAndUserIdForUpdate（SQL 的 FOR UPDATE）把会话行锁住，然后再查一次幂等——防止两个并发请求同时通过第一次检查。
  4. 双写：persistFeedback upsert 反馈表； chatMessageMapper.updateFeedback 同步消息表的冗余列。
为什么查两次幂等？这是教科书式的「检查-加锁-再检查」（check-lock-check）： 第一次检查挡掉 99% 的重复请求（省锁），拿锁之后再查一次挡掉并发间隙。 单看任何一次都不够，合起来才对。

四、快照：反馈行自己存一份问答

persistFeedback 里新建行时调 ChatFeedbackSnapshotResolver.populate(row, message)， 把当时的问题文本、回答文本、智能体名拷进反馈行（QUESTION_TEXT/ANSWER_TEXT/AGENT_NAME）。

为什么冗余拷贝而不是 join 查消息表？因为消息可能被删、被改。 快照让反馈分析页拿到的永远是「用户评价那一刻看到的内容」， 配合 ASSOCIATION_STATUS 标记「原会话还在不在」。 教训：凡是"事后审计/分析"类数据，优先考虑快照而不是外键 join。

五、Mapper 与 Entity：最少代码的一层

entity/ChatFeedback.java · mapper/ChatFeedbackMapper.java
@TableName("FM_SQUARE_CHAT_FEEDBACK")
public class ChatFeedback extends BaseEntity { /* 字段即列名驼峰映射 */ }

public interface ChatFeedbackMapper extends BaseMapper<ChatFeedback> {}

MyBatis-Plus 模式下：实体类用 @TableName 声明表名，字段自动映射列名； Mapper 接口继承 BaseMapper 就白拿 insert/selectOne/selectPage/updateById 等全套方法，连 XML 都不用写。Service 里条件查询用 LambdaQueryWrapper（编译期类型安全）或 QueryWrapper（手写列名）。

六、这张表没有 U 和 D

CRUD 里这张表实际只有 C + R：

  • Update 被业务禁掉：第一次提交后 FEEDBACK 非空，再提交不同值就抛错——「评价不可修改」是产品决策，用代码强制。
  • Delete 没有接口：会话删除时消息和附件会被清理，但反馈行故意保留——分析页要的就是"当时发生过差评"这个事实，靠 ASSOCIATION_STATUS 标记原会话已不存在。

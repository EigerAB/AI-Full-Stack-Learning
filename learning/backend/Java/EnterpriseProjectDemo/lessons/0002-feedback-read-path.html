查询链路：反馈分析页的四只 SQL

目标：看懂管理端「监控管理 → 反馈分析」页的四个接口如何共用一个查询条件构造器， 以及企业级查询的三个标配：组织隔离、分页、聚合统计。

一、一个页面 = 四个接口

controller/ChatFeedbackController.java · service/chat/feedback/ChatFeedbackQueryService.java
页面元素端点Service 方法SQL 形态
反馈列表GET /chat/feedbackslist()selectPage 分页

控制器上挂 @AdminAuth——管理员才能进这个域。所有方法走同一个 query(param) 私有方法构造条件，四个接口共用一套过滤逻辑，永远不会出现"列表能筛、统计不能筛"的不一致。

二、共用查询条件：query() 逐行读

var q = new QueryWrapper<ChatFeedback>()
    .eq("ORG_CODE", org)                    // ① 组织隔离（永远第一个条件）
    .isNotNull("FEEDBACK")                  // ② 只看已评价的（预占位行被排除）
    .ge("FIRST_FEEDBACK_TIME", p.getFrom()) // ③ 时间范围
    .lt("FIRST_FEEDBACK_TIME", p.getTo());
if (p.getAgentProductId() != null) q.eq("AGENT_PRODUCT_ID", ...);   // ④ 可选筛选
if (p.isUnassignedAgent())         q.isNull("AGENT_PRODUCT_ID");    //    「未关联智能体」反选
if (p.getFeedback() != null)       q.eq("FEEDBACK", ...);
if (p.getProblemType() != null)
    q.apply("INSTR(',' || PROBLEM_TYPES || ',', {0}) > 0", ",irrelevant,"); // ⑤
if (p.getKeyword() != null)
    q.apply("INSTR(NOTE, {0}) > 0", p.getKeyword().trim());               // ⑥

三个值得记住的点：

  • 组织隔离不是可选项，是构造器的第一行。access.requireManagementOrganization() 先取当前管理员所属组织，然后所有 SQL 都强制带 ORG_CODE = ?。 管理员永远看不到别的组织的数据——这种约束要焊死在查询构造器里，而不是靠每个接口记得加。
  • ⑤ 暴露了存储设计的代价：PROBLEM_TYPES 存的是逗号串（"irrelevant,missing"）， 筛选时只能 INSTR(',' || col || ',', ',x,') 包边界匹配——走不了索引，也容易写错。 规范做法是关联子表。这里是「最多 4 个枚举值、数据量小」的务实取舍：看到逗号串字段时，要能说出它省了什么、牺牲了什么。
  • apply() + {0} 占位符 是 MyBatis-Plus 手写 SQL 片段的安全方式——值走参数绑定，不拼字符串，防注入。

三、统计接口：一条 SQL 算完所有卡片

.select("COUNT(*) AS TOTAL",
        "SUM(CASE WHEN FEEDBACK='good' THEN 1 ELSE 0 END) AS GOOD_COUNT",
        "SUM(CASE WHEN FEEDBACK='bad'  THEN 1 ELSE 0 END) AS BAD_COUNT",
        "SUM(CASE WHEN INSTR(...) > 0 THEN 1 ELSE 0 END) AS IRRELEVANT", ...)

summary() 用 mapper.selectMaps(q) 拿单行多列的聚合结果。 注意注释："Single SQL snapshot keeps the numerator and denominator consistent"—— 如果只查两次（先查总数再查差评数），两次之间插入一条新数据，差评率就算歪了。 同一画面的统计数字必须用同一条 SQL 的快照产出。

四、详情接口：快照 + 存活探测

detail(id) 做的事体现了快照设计的另一半：

  1. 查反馈行（照样带 ORG_CODE + FEEDBACK IS NOT NULL）；
  2. sessions.findBySessionIdAndUserId(...) 探测原会话是否还在 → sessionAvailable；
  3. 会话还在才去消息表找原消息、查 FM_SQUARE_CHAT_RUN_TASK 的任务进度、拉上下文； 会话没了就直接返回快照字段，详情页照样能看。
模式识别：快照保证"底线可看"，在线关联提供"增强信息"。 两层分开，原数据删除时详情页优雅降级而不是 404。

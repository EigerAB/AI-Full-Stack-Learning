## 2. 主项目：ruoyi-vue-pro（芋道）

### 为什么适合

它采用 Spring Boot 多模块结构，使用 MyBatis-Plus、Redis 和 Spring Security，提供系统管理、数据权限及 AI 等模块，另有 Vue 3 管理端。技术与当前课程有较大交集，也方便发挥你的前端经验。[仓库说明](https://github.com/YunaiV/ruoyi-vue-pro)

AI 模块包含模型接入、向量存储和 MCP 客户端/服务端依赖，可以继续研究聊天、知识检索及工具集成，而不止停留在增删改查。[AI 模块源码与依赖](https://github.com/YunaiV/ruoyi-vue-pro/tree/master-jdk17/yudao-module-ai)

### 必须选对分支

选择 **`master-jdk17`**。本次核验时默认 `master` 仍是 Java 8 + Spring Boot 2.7.18。不能因为项目主页写着支持 Boot 3，就直接下载默认分支。[默认分支 POM](https://github.com/YunaiV/ruoyi-vue-pro/blob/master/pom.xml)、[Java 17 分支 POM](https://github.com/YunaiV/ruoyi-vue-pro/blob/master-jdk17/pom.xml)

### 怎么学

1. 先阅读一个简单的配置或字典管理接口，跟踪 Controller → Service → Mapper。
2. 自己增加“学习资源”模块，练习标题、分类、链接的新增、分页和修改。
3. 给资源增加权限，验证不同账号能看到和操作哪些数据。
4. 学到 AI 章节时再开启 AI 模块，练习会话管理、知识库和引用来源。

以上是建议的练习顺序，不是要求今天就部署整个项目。

### 环境与差异

基础后台按官方启动文档需要 MySQL 和 Redis；前端体验需要另行准备对应前端项目。AI 模块需要按文档启用，模型调用和向量存储再按选定方案配置。[后端启动文档](https://doc.iocoder.cn/quick-start/)、[AI 功能开启文档](https://doc.iocoder.cn/ai/build/)

它是 Spring Boot 多模块应用，当前课程按模块化单体阅读，system、infra 由 yudao-server 组合运行。项目封装较多，先理解普通 Spring 写法，再阅读框架封装。

许可证为 [MIT](https://github.com/YunaiV/ruoyi-vue-pro/blob/master-jdk17/LICENSE)。代码授权与模型服务、云资源费用是不同的事情；本次没有购买或订阅任何服务。

## 3. AI 专项：Spring AI Alibaba Examples

这是示例集合，适合用一个小工程学清一个能力。根目录列出了聊天、RAG、MCP、工具调用等子项目，基础聊天示例可先只配置模型 API Key，暂时不部署整套业务后台。[README 与快速启动表](https://github.com/spring-ai-alibaba/examples/blob/main/README.md)

建议按下面顺序学习：

1. `spring-ai-alibaba-helloworld`：发出请求并拿到模型回复。
2. 聊天和记忆示例：区分当前消息、历史消息与会话。
3. 工具调用示例：让模型请求调用一个受控的 Java 方法。
4. RAG 示例：把自己的公开笔记作为检索资料。
5. MCP 示例：把已有能力通过协议暴露或接入。

这些名称可以从 [仓库模块列表](https://github.com/spring-ai-alibaba/examples/blob/main/pom.xml) 找到。部分目录是聚合模块，**实际启动哪个子模块，以该目录的 README 和 POM 为准**，不能认为每个目录都有可运行的 `main` 方法。

基础示例环境较轻，RAG、MCP 等示例所需服务各不相同。云模型调用可能产生费用，不能因为代码开源就认为接口免费。该项目也不是带完整用户、权限和后台管理的成品系统。

许可证为 [Apache-2.0](https://github.com/spring-ai-alibaba/examples/blob/main/LICENSE)。框架本身在另一个仓库 [alibaba/spring-ai-alibaba](https://github.com/alibaba/spring-ai-alibaba)，提供 Agent、Graph 等能力；当前阶段优先学 Examples，不必先研究框架源码。

## 4. 业务补充：mall

mall 是电商后端，包含商品、订单、权限与搜索等模块，适合补充 AI 项目中不一定充分出现的业务规则和事务练习。选择 `master`，其 README 明确区分 Java 17/Boot 3.5 与旧版本分支。[仓库说明](https://github.com/macrozheng/mall)

建议先看 `mall-admin` 的品牌或商品分类管理，再研究订单状态流转。完整系统包含更多服务，不建议第一天就把所有功能一起启动。后台开发配置可看到 MySQL 和 Redis；搜索等模块另有依赖。[后台开发配置](https://github.com/macrozheng/mall/blob/master/mall-admin/src/main/resources/application-dev.yml)

需要区分：它主要使用 **MyBatis + MyBatis Generator + PageHelper**，并非课程主线的 MyBatis-Plus。我们借它学习 SQL、分层和业务处理，不照搬每一个工具选择。[根 POM](https://github.com/macrozheng/mall/blob/master/pom.xml)

建议练习：给商品分类增加业务校验；给订单增加明确的状态转换规则；编写失败回滚的测试。根 POM 本次读取时设置了 `skipTests=true`，所以不能把默认构建成功当作测试已执行的证据。

许可证为 [Apache-2.0](https://github.com/macrozheng/mall/blob/master/LICENSE)。普通本地业务练习无需接入真实支付和云存储，后续确有需要时再配置。

## 6. 与课程怎样衔接

| 课程阶段 | 练习安排 |
| --- | --- |
| 第 02—03 章：JavaSE、Spring 核心 | 完成独立示例，再阅读芋道集合工具、通知公告组件与注入写法 |
| 第 04—09 章：API、数据库、业务、测试 | 自建学习资源服务；参考芋道简单模块，自己写完整请求链 |
| 第 10—13 章：权限、缓存、并发、通信 | 阅读芋道对应实现，给自己的服务逐项增加能力 |
| 第 14—16 章：微服务、消息、部署 | 用独立练习理解拆分与调用失败；不要求把芋道主应用提前拆成微服务 |
| 第 17—18 章：AI 与综合实践 | 先跑 Examples 单项实验，再参考芋道 AI 模块，完善个人知识助手 |

最终练手题目建议是 **“个人学习资源与知识问答平台”**：管理笔记和链接，提供账号权限、检索、流式问答与引用来源。这样功能随课程逐步增加，既能独立在家练习，也能用公开仓库对照实现。

课程与练习统一以芋道及独立教学示例为依据，项目扩展按章节逐步增加。

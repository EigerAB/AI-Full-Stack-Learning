## 1. 先建立整体认识

这是一个 Spring Boot 多模块项目。基础运行时，`yudao-server` 引入 system、infra 等模块，把它们组合成一个应用；一个模块不等于一个独立进程。

| 位置 | 职责 | 对应课程 |
| --- | --- | --- |
| `pom.xml` | 聚合模块、编译级别、插件和版本属性 | 第一章 Maven |
| `yudao-dependencies/pom.xml` | 集中管理依赖版本的 BOM | 第一章依赖管理 |
| `yudao-framework` | 通用代码及 Web、安全、数据访问等 Starter | 第三章配置，后续工程能力 |
| `yudao-server` | 应用启动、配置、组装业务模块 | IDE 实操、Spring Boot |
| `yudao-module-system` | 用户、权限、字典、通知公告等业务 | 主要入门阅读模块 |
| `yudao-module-infra` | 配置、文件、任务等基础业务 | 后续专题 |
| `yudao-module-ai` | 模型、聊天、知识库等能力 | 第 17 章；默认未启用 |
| `sql/mysql` | MySQL 初始化脚本 | 数据库课程 |

根 POM 的 modules 和 yudao-server 的 dependencies 都需要看。其他业务目录即使存在，仍可能被注释而不参与基础应用构建。无需为了读源码而一次启用所有模块。

## 2. 第一条业务链：通知公告分页查询

选择它是因为链路清晰，能依次看到请求参数、权限、业务调用、查询和返回值。以下路径均相对于项目根目录。

| 顺序 | 文件 | 先看什么 |
| --- | --- | --- |
| 1 | `yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/controller/admin/notice/NoticeController.java` | getNoticePage，@GetMapping、@PreAuthorize、@Resource |
| 2 | `yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/service/notice/NoticeService.java` | 接口声明：需要提供哪些业务能力 |
| 3 | `yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/service/notice/NoticeServiceImpl.java` | getNoticePage 调用 noticeMapper.selectPage |
| 4 | `yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/dal/mysql/notice/NoticeMapper.java` | 标题模糊筛选、状态筛选、按编号降序 |
| 5 | `yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/dal/dataobject/notice/NoticeDO.java` | 数据库对象与字段 |
| 6 | `yudao-module-system/src/test/java/cn/iocoder/yudao/module/system/service/notice/NoticeServiceImplTest.java` | 查询筛选如何用测试数据验证 |

Controller 中的请求对象是 NoticePageReqVO，响应对象是 NoticeRespVO。名称中的 VO 是项目约定，不要仅靠后缀判断它只能表示哪一种对象；先看实际是接收参数还是返回数据。

当前查询声明是 `/system/notice/page`，Web 配置给管理控制器添加默认 `/admin-api` 前缀，因此默认访问路径为 `/admin-api/system/notice/page`。还要满足登录、租户及 `system:notice:query` 权限，最终以运行配置为准。

当前阶段只读查询；新增、修改和删除留到后续业务练习，避免在尚未理解数据与权限时执行写操作。

## 3. 第二章看集合与通用数据类型

- `yudao-framework/yudao-common/src/main/java/cn/iocoder/yudao/framework/common/util/collection/CollectionUtils.java`：从 convertList 方法观察泛型、函数参数、Stream 和空值过滤。
- `yudao-framework/yudao-common/src/main/java/cn/iocoder/yudao/framework/common/pojo/PageResult.java`：分页结果怎样组合总数和列表。
- `yudao-framework/yudao-common/src/main/java/cn/iocoder/yudao/framework/common/pojo/CommonResult.java`：通用响应怎样使用泛型表示不同业务数据。

看到 `BeanUtils.toBean`、`BaseMapperX`、`LambdaQueryWrapperX` 等名称时，先识别它们是项目封装，不要求立刻展开全部实现。学会原生语言/框架能力之后，再看封装解决什么重复工作。

## 4. 第三章看容器与注入

启动类：`yudao-server/src/main/java/cn/iocoder/yudao/server/YudaoServerApplication.java`。

它显式声明 scanBasePackages，扫描配置给出的 server 与 module 包。`NoticeServiceImpl` 通过 @Service 注册，`NoticeController` 与 Service 通过 @Resource 字段获取协作者。

课程独立例子用构造器注入，是为了把依赖声明得更清楚；芋道现有字段注入也由容器负责，不要认为“没写构造器就没有依赖注入”。NoticeMapper 接口由 MyBatis 相关配置建立代理，属于另一类 Bean 来源。

## 5. 启动和调试看哪些文件

- 构建应用：`yudao-server/pom.xml`，其中配置可执行 JAR 打包，产物名为 `yudao-server.jar`。
- 公共配置：`yudao-server/src/main/resources/application.yaml`。
- 本地配置：`yudao-server/src/main/resources/application-local.yaml`，本次看到端口为 48080。
- MySQL 脚本：`sql/mysql/ruoyi-vue-pro.sql`；其他脚本按对应功能需要处理。
- Web 前缀规则：`yudao-framework/yudao-spring-boot-starter-web/src/main/java/cn/iocoder/yudao/framework/web/config/WebProperties.java`。

本地没有 Maven Wrapper，命令使用已安装 Maven。在根目录可先执行 `mvn -v` 检查，再按需运行 `mvn -pl yudao-server -am compile`。这是构建步骤，不会准备数据库，也不会启动应用。

基础运行需要根据官方说明准备 MySQL、Redis 和合适的本地配置；配置中的默认连接信息不代表本机服务已存在，不要把实际凭证写进学习笔记。

具体断点步骤见 [VS Code 实操课](实操01-VSCode运行与调试Java.md)，以通知公告 getNoticePage 为入口。
